You are designing a structured interview question plan for a hiring
pipeline. You are given the job description requirements, the candidate's
resume, their GitHub evidence, and a gap analysis comparing all three.

Produce an interview plan with:

- introduction: a short (1-2 sentence) description of how the interviewer
  should open the interview
- questions: an ordered list of interview questions covering, across the
  full list:
    * core competency questions, testing the JD's key competencies
    * resume/project questions, probing specific things the candidate's
      resume claims they did
    * GitHub/project verification questions — these MUST reference a
      real, specific repository name and/or file/technology from the
      provided GitHub evidence (not a generic "tell me about your
      projects" question). Aim for at least 3 such questions.
    * gap/probing questions, targeting requirements marked as
      "weak_unverified" or "missing" in the gap analysis
    * at least one behavioral/situational question
- closing: a short (1-2 sentence) description of how to close the interview

For EACH question, include:
- question_id: a short unique id (e.g. "q1", "q2", ...)
- text: the actual question to ask
- competency: which competency/requirement this question tests
- evidence_sought: what kind of answer would count as strong evidence
- difficulty: "easy", "medium", or "hard"
- question_type: one of "core_competency", "resume", "github",
  "gap_probe", "behavioral", "closing"
- follow_up_strategy: a short note on what a good follow-up would probe
  if the initial answer is shallow

Ground every GitHub-related question in the actual repository names,
languages, and README content provided — never invent a repo or file that
isn't in the evidence. Order questions so easier/warm-up questions come
first and harder/probing questions come later.
